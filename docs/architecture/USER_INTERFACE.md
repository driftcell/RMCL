# 桌面界面与 GPUI 桥接

状态：启动器壳、实例创建与隔离迁移、Fabric/Quilt/Forge/NeoForge 加载器安装、本地与 Modrinth 远程 Mod/资源包/光影管理（资源包封面/格式兼容/优先级、光影加载器状态与当前选择）、服务器收藏、精选服务器发现、一键进服与首页快速连接、GitHub Release 自动更新、下载、设置、离线/正版/外置登录账户、皮肤头像、官方皮肤页与 3D 预览和任务日志界面已实现

## GPUI Kit 基线

桌面应用使用 `gpui-kit = 0.8.1`，由其统一提供匹配的 `gpui-pre = 0.3.10`、Base、Component 和默认 assets。应用只直接依赖 `gpui-kit` 并导入 `gpui_kit::*`，不单独覆盖 GPUI 包或混用其他快照。

应用启用默认 `component + assets`，并使用 `gpui_kit::assets::AllAssets` 获取完整 Lucide 图标目录（约多 1 MiB）。没有启用 `gpui-fast`、speech、tree-sitter、inspector 或 profiler，也没有 mold/LTO 等二进制优化。

平台依据：[GPUI Kit Installation](https://gpui-kit.com/docs/installation)。macOS 需要 15+ 和 Xcode Command Line Tools；Windows 需要 Windows 10+、MSVC C++ 工具链、Windows SDK 和 CMake；Ubuntu 24.04 的 CI 安装文档列出的 fontconfig、Wayland、WebKitGTK、XKB/X11、SSL、zstd 和 Vulkan 开发库。Linux 显示窗口还需要图形会话和可用 Vulkan 驱动，headless CI 编译不能代替运行验证。

调研记录：[GPUI Kit 技术验证](../../notes/development/gpui_kit_bootstrap.md)、[界面重做与配置记录](../../notes/development/ui_redesign.md)。

## 窗口与导航

窗口使用 GPUI Kit 的 `TitleBar::window_options()` 自定义标题栏，默认尺寸 1180×780，最小 980×640。macOS 保留原生红绿灯；Windows 和 Linux 使用 TitleBar 自带的窗口控制。标题栏左侧只保留 RMCL 品牌标记（简化 R）、名称和版本，右侧仅保留明暗主题切换；任务状态统一由底部任务栏展示。

主界面是常驻侧栏 + 内容区的桌面壳：

- 侧栏宽 232px，包含“主页”“实例”“皮肤”“服务器”“下载游戏”“AI 助手”“设置”和“日志”。日志放在“应用”分组的最后，处于侧栏导航最下方；任务运行中显示 spinner，任务失败或游戏异常退出后显示红点。
- 侧栏底部是当前账户卡片和编辑按钮，账户状态在所有页面可见；正版账户显示官方皮肤头像，离线账户和外置登录账户显示玩家名首字母。
- 内容区底部是常驻任务栏，显示任务阶段、当前文件、进度、停止按钮和平台信息。切换页面不会丢失任务状态。主页不重复展示进度条，底栏是唯一常驻进度位置。
- 页面之间使用即时切换，不做 HMCL 式转场动画。颜色、间距和圆角优先来自 GPUI Kit 语义 token；侧栏宽度、图标尺寸、虚拟列表行高等物理边界使用明确的像素值。
- 用户主目录下的只读路径统一显示为 `~/…`；可编辑的目录或 Java 路径输入框保留完整路径。

## 页面

### 主页

- 大号启动卡片：实例图标、显示名称、类型和发布时间、实际游戏目录；旧共享实例额外显示“共享”标签，已隔离实例不再重复标注。
- “启动配置”面板：可搜索的已安装实例下拉框和主启动按钮；账户切换统一通过侧栏底部账户卡片完成，不在启动卡片中重复提供选择器。
- 没有实例时显示“安装第一个实例”入口；没有账户时显示添加账户入口，并禁用启动。
- “最近实例”卡片列出最多三个已安装实例，可直接启动。
- “快速连接”区域最多显示三个收藏服务器，每台服务器独立成卡并使用与联机精选一致的布局；显示服务端图标（提供 favicon 时）、在线状态、延迟、人数和 MOTD，直接使用主页当前选中的实例和账户进入；主页可见时与“联机”页一样每 5 秒刷新状态。没有收藏时提供添加服务器和浏览精选入口，缺实例、账户或已有任务时禁用按钮并说明原因。
- “快速操作”卡片提供安装新版本和打开游戏目录。
- 主页不重复展示下载进度；进度、当前文件和停止入口只在底部任务栏。

### 实例

- 扫描 `versions/<id>/<id>.json`，读取可选的 `rmcl.instance.toml`，显示有效实例；按发布时间从新到旧排序。
- 搜索框按实例 ID、显示名称和基础 Minecraft 版本过滤，并提供“全部 / 正式版 / 快照 / 旧版”筛选。
- 每行显示显示名称、基础版本、加载器（若有）和实际游戏目录；旧共享实例显示“共享”标签。manifest 损坏时标记“配置异常”，但仍允许修复或删除。
- 顶部“新建实例”进入创建页；每行提供启动、管理内容、检查并修复、启用版本隔离、打开游戏目录和删除。检查修复复用 `VersionSource::Existing`，不新增第二套安装逻辑。
- 有共享实例时页面顶部显示迁移提示；没有 manifest 的旧版本显示“共享”标签。点击启用隔离后弹出确认，确认后把全局 mods、资源包和光影中缺失的文件复制到实例，不覆盖已有文件，原全局内容保留。
- 正常启动走已安装快速路径：读取版本 JSON、生成计划并检查 client、libraries、natives 和 asset index 是否存在，不重新下载或重新哈希 asset objects。缺少基础文件时返回“版本不完整，需要修复”，不会静默启动。
- 删除只移除 `versions/<id>/`，保留共享 `libraries/` 和 `assets/`；隔离实例会同时删除自己的 mods、资源包、光影和存档，确认文案会明确说明。删除前要求版本 JSON 和 ID 匹配，并拒绝符号链接目录。
- 缺少客户端 JAR 的实例标记为“文件不完整”，仍可启动或修复；修复流程会补齐缺失文件。

### 新建实例

- 从 Mojang 官方版本列表选择 Minecraft 版本，可按版本 ID 搜索；默认选择当前实例的基础版本，否则选择最新正式版。版本列表加载失败时保留手动输入版本 ID 的回退。
- 选择 Vanilla、Fabric、Quilt、Forge 或 NeoForge；切换基础版本或加载器后自动获取加载器版本，稳定版默认优先。Forge 1.12.2 及更早的 legacy installer 不展示为可安装选项。
- 显示名称和实例 ID 可留空；ID 按基础版本和加载器自动生成，也可手动指定。
- 创建过程显示基础版本安装、加载器元数据获取、实例配置写入、Forge/NeoForge processor 进度和实例文件安装阶段。
- 创建成功后自动选中新实例并进入实例详情。

### 联机

页面内分为“收藏 / 发现”两个 tab。

“收藏”：

- 侧栏“联机”页展示全局收藏，使用当前选中实例和账户进服；服务器条目不绑定实例或账户。
- 搜索栏右侧提供添加服务器；页面可见时每 5 秒自动刷新状态。
- 每行显示服务器图标、名称、地址、MOTD、标题行右侧人数，以及状态与延迟（绿色对勾 + 延迟，失败时红色叉号 + “无法连接”）；支持搜索、编辑和删除。
- 添加/编辑对话框校验 `host[:port]`；删除只移除 RMCL 收藏，不修改游戏内 `servers.dat`。
- “进入”通过 `--quickPlayMultiplayer`（1.20 / 23w14a+）或 legacy `--server`/`--port` 启动当前实例，仍复用底部任务栏、日志和取消。
- “启动目标”与“收藏 / 发现”tab 同处一行，实例下拉框位于 tab 右侧，收藏和发现共用；账户沿用左下角当前账户，不在页面内重复提供账户选择。游戏或任务运行期间禁用“进入”，原因放在按钮悬停提示中。

“发现”：

- 展示随应用发布的精选服务器清单，显示名称、标签、简介、地址、推荐版本、实时状态，以及有官网时的图标按钮。
- 状态与延迟合并展示；首次查询显示 spinner，后续自动刷新保留旧状态并直接替换，连接失败只显示红色叉号和“无法连接”，不暴露内部错误。
- 原版条目提供“进入”和旁边的星标收藏；进入使用当前选中的实例和账户，不创建新实例。已收藏时星标填充，再次点击取消收藏。需要 Mod/整合包的条目只显示警告和官网图标，不提供自动安装。
- 不校验推荐版本；多数公共服务器通过 ViaVersion 等兼容层处理版本差异。缺实例、账户或已有任务时禁用“进入”并在悬停提示中说明原因。
- 未选择账户时禁用安装；切换 tab 会刷新对应状态，离开页面会取消请求。

### 实例详情

- 从实例行的“管理内容”按钮进入；顶部显示实例名称、加载器、基础版本、启动和打开实例目录，并提供重命名按钮；旧共享实例额外显示“共享”标签。重命名只修改显示名称，不改目录。
- 没有加载器时顶部显示“添加 Mod 加载器”：进入预填基础版本的创建页，必须选择 Fabric/Quilt/Forge/NeoForge，创建新的隔离加载器实例并复制当前实例内容；原实例保持不变。已有加载器时只显示加载器标签，不支持原地升级或更换。
- 实例摘要显示游戏目录、内容数量、Java 和启动设置；“选择 Java”列出本机探测到的 managed、`JAVA_HOME` 和 PATH runtime，也可输入自定义 `java`/`java.exe` 路径并先探测，可一键改回自动选择。显式 Java 只影响当前实例，启动前重新校验。
- “启动设置”可设置最大内存（MiB）和初始窗口宽高；留空保留 JVM/游戏默认。输入在保存时校验范围。
- 三个标签页分别管理 Mods、资源包和光影包，标签显示数量；页面显示游戏目录和每类已启用/总数。
- 搜索按显示名称和相对路径过滤；工具栏提供导入、打开内容目录和重新扫描。
- 导入使用原生文件选择器；同名文件自动改名为 `name (1).ext`，不覆盖已有文件。
- Mods 使用列表行：显示大小或“文件夹”、相对路径和状态；启用/禁用通过 `.disabled` 后缀；删除前弹出确认。
- 资源包使用双列封面网格：读取 `pack.png` 作为封面，显示真实描述、格式/兼容状态、启用状态和优先级上下移动；启用/禁用改写实例 `options.txt`。
- 光影包使用双列卡片：显示 `shaders/pack.json` 描述、文件大小和“使用中”状态；检测 Iris/Oculus/OptiFine 后可设为当前或关闭光影，缺少加载器时显示可执行提示。
- 扫描警告、元数据读取失败和 `options.txt` 错误显示为横幅，不隐藏其他内容。
- 内容操作进行中时禁用导入、切换、优先级、删除和启动，避免与游戏进程或后续扫描冲突。
- “下载内容”进入在线内容页，按当前实例的 Minecraft 版本过滤；Mod 还会按实例加载器过滤，光影包在检测到加载器后按 Iris/OptiFine 过滤。

### 在线内容

- 搜索 Modrinth 项目，支持相关度、下载量、关注数、最新发布和最近更新排序，以及分页“加载更多”。
- 项目列表显示标题、作者、描述、下载量、加载器和分类；进入项目后显示可用版本、版本类型、发布时间、游戏版本、加载器、文件名/大小和必需前置数量。
- 正式版推荐项显示“推荐”标签；推荐按版本类型和可安装/SHA-1 条件选择。
- 每个版本可安装；点击后先显示前置预检：主文件与必需前置的“已安装/已禁用/其他版本/将安装/冲突”状态、可选前置数量和警告。预检读取本地 Mod 元数据，并对主 Mod 远程 JAR 读取真实 ID、依赖和常见 semver/Maven 版本范围；主 JAR 元数据按 SHA-1 缓存。存在不兼容的已安装 Mod 时拒绝安装。
- 当前实例没有 Mod 加载器时显示警告；光影包缺少 Iris/Oculus/OptiFine 时提示安装后不会生效。安装 Mod 时会自动解析并安装 required 依赖；相同 Mod ID/版本的前置会跳过。
- 光影项目版本列表在检测到加载器时使用 Iris/OptiFine 过滤；未检测到加载器时保留全部版本并显示警告。

### 下载游戏

- 首次打开时拉取并缓存 Mojang `version_manifest_v2.json`，显示版本总数和最后获取状态。
- 搜索框按版本 ID 过滤，默认显示正式版；可切换快照和旧版，不提供“全部”标签。
- 使用 `v_virtual_list` 渲染远程版本，避免一次绘制数百行。
- 每行显示类型图标、版本 ID、类型标签、发布时间、已安装状态和安装 / 重新安装按钮。已安装状态使用绿色圆形对勾，不再占用一整枚文字标签。
- 安装按钮打开确认对话框，说明新实例默认启用版本隔离，确认后启动应用层安装任务；进度只显示在底部任务栏，不弹出阻塞式进度窗口。
- 同时只允许一个安装、修复、启动或删除操作。任务运行期间，安装、启动、修复和删除按钮都禁用，避免并发写入同一仓库。

### 皮肤

- 只显示当前选中的正版账户；离线账户、外置登录账户或未选择账户时显示空状态，并通过账户入口登录。外置登录账户的空状态说明游戏内皮肤由 authlib-injector 和认证服务器处理，RMCL 不提供第三方皮肤上传或更换。账户切换仍通过侧栏账户卡片完成。
- 左侧是独立的 3D 角色预览 Entity：默认缓慢自动旋转，可拖拽调整视角，松手后恢复旋转；切换皮肤和模型时只重绘预览区。
- 左右两张卡片等高对齐，右侧卡片不独立滚动；仅“最近使用”列表在超出剩余高度时滚动。
- 右侧显示玩家名、激活皮肤/模型和激活披风名称，并提供刷新；同步中的 spinner 显示在玩家名右侧，不插入新行改变布局。
- 提供 LittleSkin、NameMC 和 Minecraft Skins 的外链，使用系统浏览器打开；界面不提供恢复默认皮肤入口。
- 更换皮肤支持本地 PNG 和图片直链两种入口，统一进入候选预览；候选预览显示文件名、来源和经典/纤细模型选择。
- 应用和图片读取都有明确进行中状态；429 显示冷却，请求结果未知时提示先刷新确认，不自动重传。
- 最近使用展示本地皮肤库中保存的皮肤、头像和模型；点击“使用”重新载入候选预览后再次应用。
- 页面不在前台时停止预览动画；预览渲染使用物理像素尺寸，属于明确的光栅边界例外。渲染在应用层 Tokio runtime 上异步执行，UI 只显示最新完成的帧，拖动时不会阻塞事件循环。

### 日志

- 侧栏独立入口；任务运行中显示 spinner，异常后显示红点。
- 显示任务类型、状态、阶段、进度、错误、退出码或终止信号。
- 日志使用等宽字体，支持自动滚动、复制、导出到配置目录下的 `logs/`、打开日志目录和清除当前任务记录。任务阶段、进度、当前文件和停止入口只在底部任务栏；日志摘要只保留任务 ID、错误与退出状态，日志行数只在输出区域标题显示。
- 外部网页与文档使用 link 样式和手状光标；打开本地目录、执行命令和页面导航使用普通按钮与默认箭头。
- 用户手动滚动日志时自动滚动立即关闭，直到重新打开；游戏正常启动和正常退出不弹 toast，异常退出才提示并标记日志入口。
- 取消或异常退出后日志仍保留，直到用户清除或新任务开始。

### AI 助手

- 侧栏“应用”组提供独立入口；运行中显示 spinner，等待确认时显示圆点。
- 会话由 `AgentService` 持有，切换页面不打断当前回合；关闭窗口后历史只在内存中，不持久化。
- 对话使用 `MessageScroller`：用户消息右对齐 Filled Bubble，Agent 最终回复使用 Ghost Bubble 内的 `TextViewState` Markdown 渲染。
- 等待首轮时显示三个点的自定义动画；系统开启减少动态效果时改为静态点。
- 当前动作使用 `Marker`：运行中文案扫光，完成显示绿色对勾，失败红色叉号，跳过显示停止图标；同位置切换，不反复淡入淡出。
- 工具步骤完成后折叠为“已完成 N 个步骤 · 时长”，失败时自动展开；运行中的任务直接读取 `TaskManager` 快照显示进度条。
- 输入框使用自动增高的 Textarea，Enter 发送，Shift+Enter 换行；运行时发送按钮变为停止。
- 破坏性工具在页面内显示确认卡；取消、拒绝和停止分别映射为 skip/stop，不提供无确认的全自动破坏性模式。
- 未配置 Key 时显示“去设置 API Key”；设置卡片保存服务商、模型、Base URL、代理和系统钥匙串中的 API Key，并提示对话和工具结果会发送给所选服务商。

### 设置

按卡片分组，不采用 HMCL 的八标签设置树：

- **游戏**：Minecraft 目录使用原生目录选择器，Java 目录、自动获取 Java。目录修改后立即重新扫描版本，不移动现有文件；Java 目录和自动获取设置重启后生效。
- **启动行为**：启动器可见性。默认保持显示；选择“游戏运行时隐藏”后，游戏进入 `RunningGame` 阶段时隐藏启动器（macOS 隐藏应用，Windows/Linux 最小化窗口），任务退出、失败或取消时恢复。
- **AI 助手**：服务商、模型 ID、Base URL、可选 HTTP/SOCKS5 代理和系统钥匙串中的 API Key。默认服务商为无需 Key 的 Kilo 免费模型；选择 BYOK 服务商时显示 Key 输入。已保存的 Key 不回填；卡片提示对话和工具结果会发送给所选服务商，免费模型可能记录对话。
- **外观**：跟随系统 / 浅色 / 深色，以及翡翠、海蓝、紫罗兰、琥珀、玫瑰五种强调色。修改立即应用并保存。
- **更新**：当前版本、启动时检查、手动检查、发布说明、下载进度和错误。检查期间按钮自身显示 loading 和“正在检查”，检查完成且无新版本时显示“已是最新版本”，不额外占用状态行。默认从 GitHub Release 检查，下载后校验 SHA-256，退出并重启完成替换。
- **关于**：版本、配置路径、运行平台和 GPUI Kit 文档链接。

## 账户

账户模型统一展示离线、Microsoft 正版和 authlib-injector 外置登录账户：

- 离线账户由 `rmcl-auth` 生成稳定 UUID；用户名允许非传统字符，界面按原始输入保留。
- 正版账户使用 Microsoft 设备代码登录，成功后保存 profile UUID、玩家名、官方皮肤 URL 和系统钥匙串凭据。
- 外置登录账户通过内置认证服务器列表或自定义 API Root 登录；密码只用于一次登录请求，access token/client token 保存在系统钥匙串。多角色账户在登录时选择角色。
- 账户切换统一通过侧栏底部账户卡片打开账户对话框完成，主页启动卡片、实例徽标和联机启动目标不重复展示账户选择器或玩家名。
- 侧栏卡片和账户列表显示正版皮肤头像；无皮肤、离线或外置登录账户显示首字母。外置账户副标题显示认证服务器名称。
- 账户对话框支持切换、添加离线账户、正版登录、外置登录和删除。删除前弹出确认；删除正版或外置账户会同时清除系统凭据，删除当前账户后自动切换到下一个账户。
- 启动正版或外置账户时按需校验/刷新 token；刷新失败提示重新登录，不会回退成离线身份。

协议、令牌和皮肤细节见 [正版账号、令牌与皮肤](AUTHENTICATION.md) 与 [authlib-injector 外置登录](../compatibility/AUTHLIB_INJECTOR.md)。当前不包含第三方皮肤站网页解析、第三方皮肤上传、披风切换和皮肤编辑器。

## 配置与路径

启动器配置由 `rmcl-store` 持久化，默认路径：

- macOS：`~/Library/Application Support/rmcl/config.toml`。
- Linux：`~/.config/rmcl/config.toml`，`XDG_CONFIG_HOME` 存在时优先使用它。
- Windows：`%APPDATA%\rmcl\config.toml`。

基础目录由 `dirs` 按系统规则解析。配置使用 TOML、schema 版本 8（可读取 schema 1/2/3/4/5/6/7 并升级），并通过同目录临时文件、`sync` 和原子替换写入。损坏或更高版本的配置不会被静默覆盖；界面显示读取错误，设置修改仍会写入当前 schema。详细字段和错误语义见 [启动器配置](CONFIGURATION.md)。

Java store 仍使用 `~/.rmcl/java`，日志位于配置目录下的 `logs/`。RMCL 不读取或改写 HMCL 配置。

## 事件桥接与状态一致性

`apps/rmcl` 在窗口根持有 `Arc<Services>`。桌面 services 包装共享 `AppContext`，并组合以下应用层服务：

- 一个 multi-thread Tokio `Runtime`，驱动 `rmcl-app` 的安装、Java 和游戏任务。
- 一个 `TaskManager`，持有全部后台任务、取消令牌、快照和日志。
- 一个 `VersionCatalog`，缓存远程版本清单。
- 一个 `MicrosoftAccountService`，负责设备代码登录、token 刷新、系统凭据读写和启动身份解析。
- 一个 `SkinCache`，只从 Mojang 官方纹理域下载并合成头像。
- 一个 `ConfigStore`，负责 TOML 配置。
- 一个 `AgentService`，持有 BYOK Provider、Rig 对话历史和进程内 MCP 连接；AI 页面只消费事件。
- 当前目标 `Platform`，供每个请求克隆使用。

窗口重新激活时会重扫实例，并只合并外部配置中的账户、服务器收藏和选中版本；实例详情在空闲时同步重扫内容。该刷新不替换账户编辑文本或其他本地设置，不自动写回配置，也不依赖常驻文件监听。

GPUI 不使用 `block_on` 等待核心任务。按钮回调通过 `Runtime::spawn` 调用 `start_install`、`start_launch` 或 `cancel`，并在 GPUI foreground task 中 await 返回的 `JoinHandle`。传给 Tokio 的数据必须是 owned `Send` 数据，不捕获 GPUI Context 或 Window。

`TaskManager` 的广播接收器直接移入一个持久保存的 GPUI foreground task。该 task 只处理事件和短 Entity 更新，不拥有安装或游戏 future。后台任务不依赖 View 是否正在显示日志。

版本选择使用 `SelectState<SearchableVec<String>>`。账户通过侧栏账户卡片或账户对话框切换，账户列表和删除使用稳定账户键区分同名离线、正版和不同认证服务器上的外置账户。安装完成或目录切换后通过 `set_items` 更新版本选择，不重建整个 View。版本请求带稳定 `TaskId`，终态只触发一次续期、版本重扫和通知。

实例详情页的本地内容扫描、导入、切换和删除通过 `Runtime::spawn` + `spawn_blocking` 执行；界面持有短生命周期 foreground task，只负责等待结果和更新 `ContentLibrary`。这些本地操作不进入 `TaskManager`，因为它们没有长时下载或游戏进程生命周期。

Modrinth 搜索和版本列表也通过短生命周期 foreground task 调用元数据客户端，并用请求 generation/cancellation 防止旧结果覆盖新页面。远程文件安装进入 `TaskManager` 的 `ContentInstall` 任务，复用状态栏进度、取消、广播快照和实例互斥。

## 明暗主题与系统外观

`gpui_kit::init` 提供默认浅色和深色主题。应用在启动和设置变化时调用：

- 跟随系统：`Theme::sync_system_appearance`，并让原生窗口外观跟随系统。
- 浅色 / 深色：`Theme::change(ThemeMode::…)`，同时设置 macOS 原生窗口外观。
- 强调色：在主题切换后通过 `Theme::update` 覆盖 `primary`、`button_primary*`、`sidebar_primary`、`sidebar_accent`、`ring` 和 `selection`。

标题栏的主题按钮在浅色和深色之间切换；当前为“跟随系统”时，按钮根据系统实际外观切换到另一固定模式，并同步设置页选择。标题栏交互控件阻止鼠标按下事件冒泡，避免轻微指针移动被窗口拖拽截获。选择“跟随系统”时，窗口外观变化会重新应用强调色。主题和强调色修改立即保存。
