# 下载执行器

状态：当前核心行为已实现

日期：2026-10-28

## API 与依赖方向

`rmcl-net` 执行 `rmcl-domain::DownloadRequest`，不依赖 Minecraft 或安装计划。`rmcl-install::PlannedFile` 可以转换为该请求。

- `download_file`：执行一个请求，返回 `Downloaded` 或 `Skipped`。
- `download_all`：按全局并发限制执行多个请求，返回 `DownloadReport`。
- 报告包含成功结果、逐文件错误和取消状态；`is_success()` 只在无失败且未取消时为真。

安装计划与批量下载都会拒绝重复目标及仅大小写不同的冲突目标，防止并发写入同一路径，并使 Windows、macOS 和 Linux 的计划行为一致。不同批量或独立单文件任务之间的同目标写入仍需调用方串行化。

## 并发与取消

`DownloadConfig` 默认值：

- 全局并发：8
- 每主机并发：4
- 每来源尝试次数：3，包含第一次请求；只应用于最后一个候选源
- 连接超时：10 秒
- 每次尝试总超时：300 秒
- 初始重试延迟：200 毫秒，指数退避并带抖动，上限 5 秒

每主机 semaphore 覆盖一次 HTTP 尝试，不在重试等待期间占用许可。取消使用 `CancellationToken`，覆盖连接、响应读取、重试等待和批量调度。批量收到取消后会停止调度剩余请求。

## 候选来源与重试

- 按 `sources` 顺序尝试。前面的候选（通常是国内镜像）只尝试一次，最后一个候选（通常是官方源）使用 `max_attempts_per_source`；镜像故障时不会因为重试而延迟官方回退。
- 每个候选源在进入下一次尝试前重新检查取消。
- 网络错误、超时、408、429、5xx、响应截断、size 或 SHA-1 不符可以重试。
- 其他 4xx 不重试同一来源，直接转向下一候选。
- 不支持非 HTTP(S) scheme 或非 identity Content-Encoding。
- 每次尝试重新创建临时文件，不复用未验证内容。
- 全部来源失败后返回 `Exhausted`，保留逐次来源与原因。

错误和进度中的来源会移除用户信息、query 和 fragment，避免意外记录签名参数。原始 `DownloadRequest` 仍可能包含敏感 URL，调用方不应直接将其作为日志输出。

## 已有文件检查

检查按独立维度执行：

1. 目标必须是普通文件；符号链接、目录和其他类型返回错误。
2. size 不符时需要重新下载。
3. 声明 SHA-1 时流式计算现有文件哈希，size 相等也不能替代哈希。
4. 所有声明检查通过才返回 `Skipped`。
5. SHA-1 与 size 都缺失时，不把“文件存在”当作已验证，重新下载并等待完整响应。

ZIP/JAR 容器完整性、格式检查和修复策略不属于这一层。

## 下载与发布

- 请求 `Accept-Encoding: identity`，以资源原始字节计算长度和哈希。
- 响应流式写入目标同目录的 `NamedTempFile`，不将完整文件载入内存。
- 同时检查响应 `content-length`、计划 size 和计划 SHA-1；存在时才执行对应检查。
- 校验后同步临时文件，再用 `tempfile::persist` 在同一文件系统原子替换目标；该 API 不保证目录项立即持久化。
- 新内容未通过全部检查时，已有目标保持不变；失败或取消会删除临时文件。
- 发布前再次检查取消。发布本身是短操作，已经发布的文件不会因后续取消而自动撤回。

调用方应避免把不可信或并发修改的目录当作安装根。当前不解决恶意父目录符号链接或外部进程同时改写目标的问题。

## 进度

`progress_channel` 使用有界 `tokio::sync::mpsc` 通道。事件包括检查、下载、校验、完成、跳过、失败和取消，携带目标、已下载字节、可选总量和脱敏详情。

字节事件按最多约每 100ms 一次合并，阶段结束事件始终发送。通道产生背压，接收方需要持续消费；接收端关闭不会使下载失败。

## 当前不包含

- 镜像探测与选择：上层通过 [下载源策略](DOWNLOAD_SOURCES.md) 生成 `sources` 候选，执行器只负责按顺序回退
- HTTP Range 断点续传和 ETag 缓存
- 内容寻址缓存层
- ZIP/JAR 解压与容器验证
- Java、启动和 UI 集成
