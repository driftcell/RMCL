# 实例隔离方案取舍

日期：2026-10-25

状态：已形成实现决策，最终规范见 [实例与版本隔离](../../docs/architecture/INSTANCES.md)

## 背景

RMCL 原先只有 `versions/<id>/` 版本目录，启动工作目录固定为 `.minecraft` 根，因此所有版本共享 `mods/`、`resourcepacks/`、`shaderpacks/` 和 `saves/`。后续要按实例安装内容，必须先确定实例身份和游戏目录。

HMCL 的参考行为：

- 实例 ID 与 `versions/<id>/` 目录对应。
- 隔离实例的 run directory 是实例目录；非隔离实例使用仓库根。
- 新实例默认是否隔离由全局策略决定，HMCL 默认只隔离带加载器的实例。
- 加载器和内容安装最终都落到 run directory 下的标准目录。

## 备选方案

### A. `versions/<实例ID>/` 作为实例根

优点：

- 与 HMCL 隔离实例和标准版本目录一致。
- 复用现有版本扫描、删除、版本 JSON 和 natives 布局。
- 删除实例时只删除版本目录，共享 libraries/assets 保持不动。
- 不需要维护版本 ID 与实例 ID 的第二套映射。

缺点：

- 游戏存档和内容目录与版本元数据混在同一目录。
- 同一基础版本需要不同实例 ID，例如 `1.21.1-fabric`。
- 旧版本默认共享，启用隔离需要迁移。

### B. `.minecraft/instances/<ID>/` 作为实例根

优点：版本文件和游戏数据彻底分离，同一版本可对应多个实例。

缺点：

- 需要新的实例扫描、版本映射和启动路径解析。
- HMCL 不直接识别该布局。
- 删除、修复和现有 UI 都要增加一层映射。
- 迁移成本高，当前收益不足。

## 决策

采用方案 A：

- 实例 ID 是 `versions/` 下的安全单路径组件，当前与版本 ID 一致。
- RMCL 自有 `rmcl.instance.toml` 保存显示名称、基础版本、隔离模式和可选加载器。
- 新安装默认隔离；已有版本没有 manifest 时视为 legacy 共享实例，必须由用户显式迁移。
- 迁移采用“复制缺失文件、不覆盖、不跟随符号链接、最后写 manifest”的可回退流程。
- 加载器安装和内容下载后续直接使用 `InstanceLayout` 的内容目录，不再从 `.minecraft` 根推导。

## 后续

- 加载器安装需要版本继承合并和 `jar` 重定向；当前 `plan_vanilla` 仍拒绝这两类元数据。
- 内容管理需要实例级目录扫描、远程来源和任务事件，见后续内容与整合包里程碑。
- 实例级 Java、内存、窗口和启动参数尚未持久化；manifest 已保留扩展空间。
