# 许可路线取舍

日期：2026-10-25

状态：方向已决定，发布前仍有许可准备工作

## 背景

HMCL 当前 README 明确采用 GPLv3，并包含关于修改版本名称或版本号、保留版权声明的附加条款。RMCL 希望采用 MIT，但项目又会持续参考 HMCL 的功能与源码行为。

需要避免把“换了语言”“改了架构”或“改了产品名”直接当成不受原许可约束的证明。

## 考虑过的路线

### 直接衍生或移植，继续 GPLv3

允许更直接地复用 HMCL 实现和资源，但需要承担对应 copyleft 与附加条款义务。它不是当前选择的产品许可路线。

### 独立实现，原创部分采用 MIT

HMCL 只用于行为、协议、兼容性和测试对照，RMCL 自己设计并编写 Rust 实现。该路线符合当前目标，但必须通过实际开发纪律保持独立性，不能只修改 Cargo 中的许可字段。

## 最终决定

采用第二条路线，并设置以下约束：

- 不复制或贴身翻译 HMCL 源码、注释、测试数据和资源。
- 用固定 commit 记录行为依据，用独立 fixtures 验证 RMCL。
- 任何未来直接复用都必须先重新评估许可，再决定能否合并或分发。
- 发布前补齐 MIT LICENSE、版权信息、Cargo 元数据和第三方依赖许可清单。

已固化为 [独立实现与许可](../../docs/engineering/LICENSING.md)。该文档是工程路线，不替代法律意见；MIT 许可证中的具体版权行尚未确定。
